# 三项目充电/功率级状态机对比（0824 vs 0917 vs CAN_LIMA48V10A）

> 评估维度：状态机架构、状态枚举、闭环方式、节拍、安全断电时序、故障恢复、保护完整性
> 目标：横向看三个项目"MCU 管功率级"的不同范式，给 0824 找对标方向
> 日期：2026-08-19

---

## 0. 一句话总览（先说清层级不对齐）

三个项目的状态机**不是同构**——MCU 在功率链路里的角色完全不同：

| 项目 | MCU 在功率链路的角色 | 闭环方式 | 状态机层级 |
|---|---|---|---|
| **0824**（当前） | 充电阶段编排 + 开环设定点 | 模拟 IC 双环（CC/CV），MCU 不读反馈 | 2 层：充电阶段状态机 + PFC 子状态机 |
| **0917**（参考1） | **LLC 数字控制**（直接控频率） | MCU 数字 PI 真闭环 | 2 层：LLC 数字控制状态机 + PFC 子状态机 |
| **CAN_LIMA48V10A**（参考2） | 次级监管者（开环设定点 + 阶段编排） | 模拟环，MCU 开环查表/插值 | 5 层：主 + 充电子 + SCR关断 + AC保护 + 风扇 |

**关键认知**：0824 和 CAN_LIMA 是"同类范式"（MCU 开环设定 + 模拟闭环），而 0917 是另一条路（MCU 数字 PI 控 LLC）。所以 0824 的对标，主要看 **CAN_LIMA 的分层/断电/降额思想**，而 0917 提供的是"如果将来转数字控制"的升级路线。

## 1. 状态枚举与流转

### 0824 — `power_supervisor_tick_1khz`（充电阶段状态机）
```
STANDBY →(enable && vbat≥10V)→ PRECHARGE →(母线≥360V,3s超时防卡死)→ CC
CC →(电压到基准-0.5V,1s去抖)→ CV →(电压达标 && 电流≤1A,30s)→ FINISHED
任意态 → FAULT（远程清锁+撤销enable后回 STANDBY）
```
- 另有独立 `pfc_tick_1khz`：OFF→RELAY_ON→RUN→FAULT
- **CC/CV 共用一组开环设定点**（模拟 IC 自动切双环），MCU 不重设基准

### 0917 — `llc_app_tick_1khz`（LLC 数字控制状态机）
```
IDLE →(PFC ready稳定)→ PRECHECK →(100ms稳定)→ SOFTSTART →(斜坡结束)→ RUN_ENTRY_HOLD
→(电压稳定)→ RUN →(轻载)→ BURST_MODE →(重载)→ RUN
RUN/SOFTSTART/HOLD →(失电/欠压)→ STOPPING →(软关断完成)→ IDLE
FAULT →(故障解除+延时)→ IDLE   （自动重试）
```
- 含**电压 PI 闭环**（抗积分饱和 + 斜率限制 + bumpless 无扰切换）
- 软启动斜坡 + Burst 轻载包络 + 软关断（频率平滑升到 f_max）
- 另有独立 `pfc_tick_1khz`

### CAN_LIMA48V10A — 5 层状态机（主+充电子最相关）
```
主：WAITING_BATPACK → CHARGING → SILICON_OFF → WAITING_TAKE_AWAY（驻留，需断电复位）
充电子：PRE → CCM ⇄ CVM → TRI → FINISHED
SCR关断：STEP_0(关PWM)→STEP_1(延时300ms)→FINISHED(拉门极)
```
- PRE 两段软起（浮充+半额定试探 → 2s/5s 出 PRE）
- CCM/CVM **共享同一段代码**（平铺 if，无 switch）
- TRI 可回跳 CCM（仅"从 PRE 直接来"时，防误判满电）
- 过温保护**不改变阶段号**，只在返回值 OR 错误位（正交叠加），原地打嗝自愈

## 2. 闭环方式对比

| 项目 | 电压/电流环在哪 | MCU 是否读反馈修正 | PI 控制器 |
|---|---|---|---|
| 0824 | 模拟 IC（NCP4390） | 否（开环设定点） | 无 |
| 0917 | **MCU 数字 PI**（控 LLC 频率） | 是（vout 滤波→误差→PI→频率） | 有，含抗饱和/斜率/bumpless |
| CAN_LIMA | 模拟环（PWM 参考→运放/TL431） | 否（开环查表/插值） | 无 |

> 0824 与 CAN_LIMA 一致：MCU 只"给设定点"，真正的 CC/CV 双环在硬件里。0917 把闭环搬进了 MCU。

---

## 3. 安全断电时序（最该向别人学的差距）

| 项目 | 断电时序 | 评价 |
|---|---|---|
| **0824** | `outputs_off()` **同 tick 同步断** LLC_EN + 输出继电器 + PFC 继电器 | 🔴 无时序，继电器带载分断拉弧风险 |
| **0917** | ST_STOPPING：频率平滑升到 f_max → 软关断完成 → 关 PWM + 关驱动 → IDLE | 🟢 顺序正确，软关断无冲击 |
| **CAN_LIMA** | SCR 关断状态机：**先 PWM_V/I=0 → 延时 300ms（让电流自然衰减）→ 再拉门极 → 恢复浮充参考** | 🟢 顺序正确（虽 `SCR_off()` 实为空操作，切断靠 PWM=0，理念对） |

**0824 的硬伤**：`outputs_off()` 三路同 tick 清零（`llc_control.c:113-118`）。最该补的是**仿 CAN_LIMA 的"先关 LLC_EN/PWM → 延时吸余电 → 再断输出/ PFC 继电器"** 缓冲序列。

---

## 4. 故障处理与恢复

| 项目 | FAULT 模型 | 恢复方式 |
|---|---|---|
| 0824 | 显式 FAULT 态 | 需 `protect_clear_fault_async()` 清锁 + 撤销 enable（串口 STOP+CLEAR） |
| 0917 | 显式 FAULT 态 | **检测故障解除后延时 `LLC_FAULT_RECOVER_MS` 自动回 IDLE**（自愈，无人工干预） |
| CAN_LIMA | **无 FAULT 态**；错误位 OR 进返回值高 4bit（正交叠加） | 过温：原地打嗝自愈；其余：降级到 SILICON_OFF 后**锁死，需断电复位** |

> 0824 当前恢复需人工 CLEAR；**0917 的"故障解除后自动重试"值得搬**——联调时反复试错体验更好。

## 5. 保护完整性（当前实际生效，非设计意图）

| 保护 | 0824 | 0917 | CAN_LIMA |
|---|---|---|---|
| OCP 过流 | ✅ 24A（已改不超量程） | ✅ BKIN 硬件锁存 + 软件判据 | ✅ 电流判据（盲充仲裁） |
| OVP 过压 | ⚠️ PFC RUN 态 OVP 空壳 | ✅ vout/vbus 判据 | ✅ CVM 限压 |
| UVP 欠压 | ✅ | ✅ | ✅ PVD 代理 |
| AC 输入检测 | ❌ 无 | ✅ 85-265V 去抖 | ⚠️ **状态机完整但调用点被注释禁用**，实际靠 PVD |
| 温度/风扇 | ❌ 注释未接 | ✅ 有通道+NTC | ⚠️ **风扇状态机完整但 `fanFaultFlag=1` 被注释，整体未启用** |
| 降额 | ❌ 无 | ❌ 无（靠 PI 限幅） | ✅ 温度四级滞环 + 电压棘轮 + AC 1A 钳位 |
| 温度补偿 | ❌ 无 | ❌ 无 | ✅ 三点插值补偿充电电压 |

> CAN_LIMA **设计最全但大量保护被注释禁用**（AC、风扇），属"量产保守/特定机型未启用"；0824 和 0917 在温度/风扇上都没接，是初版联调的共同短板。

## 6. 节拍与编排

| 项目 | 快环 | 慢环（状态机） | 调用方式 |
|---|---|---|---|
| 0824 | SysTick 1ms | 1kHz `power_supervisor_tick_1khz` | main 1kHz tick 内 ADC copy→protect→pfc→power |
| 0917 | TIMER3 200us（PI 500us 一次） | 1kHz `llc_app_tick_1khz` + `pfc_tick_1khz` | control_loop_tick_1khz 统一调 |
| CAN_LIMA | TIM3 100us（ADC 轮询） | 10ms(100Hz) `chargeState_Running` | 单入口嵌套驱动 5 状态机，`maintick++` 无丢拍 |

> CAN_LIMA 的 `maintick++` 逐拍补齐机制保证长计时（10h）精度；0824/0917 用 SysTick g_ms 差，要注意 tick 丢失时计时漂。

## 7. 对 0824 的更新方向（综合三项目精华）

**P0 — 补最弱的安全断电（向 CAN_LIMA 借）**
- 把 `outputs_off()` 改成"先关 LLC_EN/PWM → 延时（如 50~100ms 吸余电）→ 再断输出继电器 + PFC 继电器"，灭拉弧风险。

**P1 — 故障自动恢复（向 0917 借）**
- FAULT 态检测故障解除后延时自动回 STANDBY/IDLE，联调不用每次手动 CLEAR。

**P1 — 加 AC 输入检测 + 上电自检（向 0917 借）**
- 无 AC 时直接判故障而非傻等 3s 超时；上电做一次基准/采样自检。

**P2 — 降额与温度补偿（向 CAN_LIMA 借，量产前）**
- 温度四级滞环降额 + 电池电压棘轮 + 环温补偿充电电压（需先接 NTC/风扇采样，正是你之前"温度/软件保护/风扇另评"的那块）。

**P2 — 分层清晰化（向 CAN_LIMA 借思想）**
- 把"充电阶段"与"LLC/功率控制"职责分清，0824 当前把两者混在 `power_supervisor_tick` 里尚可，但将来转数字控制时要像 0917 那样把 LLC 数字控制独立成状态机。

**不建议盲目照搬**：
- 0917 的 **数字 PI 控 LLC** 是另一条技术路线，0824 硬件是模拟双环 IC，MCU 转数字控制需改硬件拓扑，不是软件能解决的——别硬搬。
- CAN_LIMA 的"充满后锁死需断电"是产品决策（防复充），0824 联调阶段不需要这么激进。

## 8. 三项目"实际行为 vs 设计意图"风险清单（评审时注意）

| 项目 | 设计完整但当前未生效的保护 |
|---|---|
| 0824 | 温度/风扇（注释未接）、PFC RUN 态 OVP 空壳 |
| 0917 | 无明显禁用（最"所言即所得"） |
| CAN_LIMA | **AC 保护、风扇保护双双被注释禁用**；看门狗 `IWDG_Config` 注释未启用；`isBatPack*()` 短路为常量（盲充优先）；TIM4 通道 init/runtime 映射相反 |

> 评审 CAN_LIMA 类代码时务必区分"写了"和"跑起来生效"，否则会高估其保护完整性。
