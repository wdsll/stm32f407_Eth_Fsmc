## 三、当前待办（按优先级）

### 🔴 P0 — 跨模块隐式声明，可能卡编译（新发现）
`protect.c:87` 调用 `power_supervisor_enter_fault()`，但：
- 该函数在 `llc_control.h:11` 声明；
- `protect.c` 的 includes 只有 `protect.h` / `adc_dma.h` / `pwm_llc.h`（**无 `llc_control.h`**）；
- `protect.h` 也未前向声明它。

后果：
- **Keil armcc v5（默认）**：仅 `#254` 警告（假设返回 int），链接能过、运行通常不出错（void/void 调用约定一致）。
- **Keil armclang v6（clang 前端）**：`implicit-function-declaration` 直接报 **error**，**编译失败**。

修复（二选一，建议加 include）：
```c
/* protect.c 顶部增加 */
#include "llc_control.h"
```
或在 `protect.h` 加前向声明 `void power_supervisor_enter_fault(void);`。
> 这是唯一可能让"现在这版"编译不过的点，建议最先处理。

### 🟠 P1 — PFC_STATE_RUN 仍是空壳（旧硬伤仍在）
`pfc_control.c:69-72`：
```c
case PFC_STATE_RUN:
    /* 监控母线电压: ... 加入OVP的保护*/
    break;   // ← 只有注释，没有任何母线监控
```
进 RUN 后母线过压 MCU **完全不接管**，只靠 `protect` 模块 + NCP1654 自身保护兜底。第一版能跑，但等于 PFC 裸奔，量产前必须填：
```c
if (g_adc_multi.bus_vol_v > VBUS_OVP_V) protect_set_fault(FAULT_BUS_OVP);
if (g_adc_multi.bus_vol_v < VBUS_UVP_V) protect_set_fault(FAULT_BUS_UVP);
```
（注意：`pfc_is_ready()` 里的 `bus<=VBUS_OVP_V` 只是 RUN 准入门禁，不是 RUN 内的持续保护。）

### 🟠 P1 — 安全断电无缓冲时序（三项目对比 B1，仍在）
`llc_control.c:113-120` `outputs_force_off()`：同 tick 同步断 `LLC_EN` → 复位 PWM → 断 `OUT_RELAY` → `pfc_disable()`。缺少「先关 LLC_EN/PWM → 延时吸收余电 → 再断继电器」的时序，继电器有带载分断（拉弧）风险。初版低压负载下风险低，量产前建议补（参考 CAN_LIMA 的 PWM=0→300ms→拉门极）。

### 🟡 P2 — 过期注释会误导维护者
- `llc_control.c:340` `//B3：CC 超时=8s(调试值)，正常应 8h` —— 实际已是 8h，注释错。
- `llc_control.c:361` `//B3：CV 超时=3s(调试值)，正常应 3h` —— 实际已是 3h，注释错。
- `llc_control.c:29` 宏注释写「→报 BUS_UVP」，实际已报 `FAULT_OUTPUT_START_TIMEOUT`，注释错。
- `llc_control.c:6-9` 头注释「CV 模式应切换基准」与实现矛盾（A2，已在 :9 自标注，建议统一）。

### 🟢 按约定未评（温度/风扇/软件保护 NTC）
`protect.c:132-135` 四路过温整段注释、NTC 采样未接——你要求先不管，初版联调零影响，但量产前必须补。

## 四、联调前置条件（重申，非缺陷）

1. 电池端 `vbat ≥ 10V`（STANDBY→PRECHARGE 硬条件，模拟电池用稳压源+电子负载）
2. PFC 母线稳态 `≥ 360V`（`LLC_ENTRY_V`）才进 CC；母线若只到 ~320V 会 3s 超时锁 FAULT
3. 串口每 5s 需 `PING`（看门狗自动 STOP）
4. AC 输入需落在 `[180,264]V RMS`（否则 `pfc_is_ready` 永不满足）

## 五、一句话

结构已能支撑初版联调且比前几版干净；**动手前先把 P0 的跨模块 include 补上**（否则 armclang 直接编不过），再填 PFC_RUN 的 OVP 与断电缓冲时序即可进入联调。
