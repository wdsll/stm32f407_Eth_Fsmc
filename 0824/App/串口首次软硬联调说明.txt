## 接线和串口参数

- USB-UART GND 与控制板 GND 共地。
- USB-UART RX 接 PB10（板端 TXD），TX 接 PB11（板端 RXD）。
- 115200 baud、8 data bits、no parity、1 stop bit、无流控。
- 首次高压上电应使用限流电源/隔离措施和急停，先在低压、功率级禁止条件下验证命令与 ADC 状态。

## 命令

命令不区分大小写，以回车结尾：

```text
HELP
STATUS
SET 58.0 3.0
START
PING
STOP
CLEAR
```

- `SET <V> <A>`：仅停止时允许；范围 10–80 V、0–20 A。
- `START`：需要有效设定值且无软/硬件故障。
- `PING`：使能后至少每 5 s 发送一次；超时自动撤销使能并安全回待机。
- `STOP`：优先执行，撤销功率使能请求。
- `CLEAR`：必须先 STOP，且硬件故障输入已释放；10 ms 清故障脉冲由 1 kHz 任务异步完成，不阻塞主循环。
- 固件每 500 ms 主动输出一行 `STAT`，包含状态、故障、设定和关键 ADC 量。

## 推荐联调顺序

1. 不接高压，烧录后确认启动 banner、帮助信息和周期 `STAT`。
2. 用校准源逐路验证 AC、母线、输出、电池、电流 ADC 的方向、零点和比例。
3. 执行 `SET 58.0 3.0`，示波器确认 CV_PWM/CC_PWM 占空比，暂不执行 START。
4. 低压/限流条件接入功率板，发送 `START` 后持续 `PING`，逐项确认 PFC relay、母线建立、LLC_EN、输出继电器顺序。
5. 任一步异常立即 `STOP`；记录 `STAT` 的 state/fault 和波形。确认硬件故障已释放后才执行 `CLEAR`。
6. 串口阶段稳定并完成安全断电时序参数标定后，再启用 CAN 适配层；CAN 命令应继续只调用 `power_supervisor_set_references()` 和 `power_supervisor_request()`，
不把通信逻辑塞回状态机。


## 非阻塞约束

串口发送任务每次主循环只在发送数据寄存器空时写入一个字节，不等待硬件发送完成；运行期 `CLEAR` 也不调用忙等待延时。
因此正常的状态打印和清故障操作不会阻塞 1 kHz 监控任务。格式化和命令解析仍是同步 CPU 运算，但输入行限制为 64 字节、单条输出限制为 255 字节，不存在等待外设的无限阻塞。
