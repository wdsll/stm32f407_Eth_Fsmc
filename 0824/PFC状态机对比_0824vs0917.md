# PFC 状态机对比：0824 vs 0917

> 定位：两个项目都是 **NCP1654 外置 PFC 控制器 + MCU 只做继电器控制与监控** 的架构。
> MCU 不跑 PFC 电流环，PFC 闭环由模拟 IC 完成，MCU 负责"合继电器→等母线建立→监控 OVP/UVP→故障脱扣"。
> 所以两版 PFC 状态机本质职责相同，差异全在 **时序协调、输入自检、去抖粒度、故障恢复** 这几层。

---

## 1. 状态结构对比

| 0824（精简 4 态） | 0917（分层 4 态） | 对应关系 |
|---|---|---|
| `PFC_STATE_OFF` | `PFC_ST_IDLE` | 待机 |
| `PFC_STATE_RELAY_ON` | `PFC_ST_RAMP` | 合继电器 / 等母线爬坡 |
| `PFC_STATE_RUN` | `PFC_ST_READY` | 母线就绪 / 运行监控 |
| `PFC_STATE_FAULT` | `PFC_ST_FAULT` | 故障脱扣 |

两版状态数相同、语义等价。但 0917 的每个状态内部塞了大量**去抖 + 上电自检 + AC 有效性判断**，0824 是"直进直出"的裸骨架。

---

## 2. 逐项差异

### 2.1 AC 输入检测（⚠ 最大安全缺口）
- **0824**：**完全没有 AC 检测**。`pfc_enable()` 直接合继电器等母线，不管 AC 接没接、电压正不正常。
- **0917**：`pfc_ac_ok_debounced()` 判断 AC RMS ∈ [85, 265]V，双向去抖（ok/loss 各 200ms）。AC 异常时 IDLE 阶段根本不拉继电器，且运行中 AC 掉电经 `pfc_ac_loss_debounced()` 回 IDLE。

### 2.2 上电自检（1.414 比例）
- **0824**：无。
- **0917**：`pfc_sample_inputs()` 里做 `VBUS ≥ 1.414 × VAC`（容差 5%，稳定 50ms）自检，验证整流桥/输入正常后才允许拉继电器。**只在硬件未使能前检查**，避免 PFC 工作后误判。
  
  这条对初版联调很有用：能区分"AC 没接/整流桥坏"和"母线没建起来"两种故障。

### 2.3 启动时序（延时/爬坡/就绪）
- **0824**：合继电器后单门限等母线 `bus_vol_v >= VBUS_MIN_START_V(350V)` → RUN；超时 3s → FAULT。
- **0917**：三层时序——`PFC_STARTUP_DELAY_MS(1000ms)` 启动延时 → 拉继电器 → `RAMP_DELAY(100ms)` 爬坡 → 母线进 **[359, 379]V 范围** 并稳定 `READY_DELAY(80ms)` → READY；爬坡超时 800ms → FAULT。

  ⚠ 0824 的隐患：进 RUN 门限（350V）和 `pfc_is_ready` 的 `LLC_ENTRY_V(360V)` 不一致，母线若在 350–360V 徘徊，会"进 RUN 但 is_ready 永不真"，且进/出门限都是 350V 有边界抖动风险。0917 用"进 RAMP 条件 + READY 范围 + 掉电门限 345V"三层分离，更干净。

### 2.4 去抖粒度
- **0824**：仅 RUN 态有 OVP(20ms)/UVP(200ms) 去抖。
- **0917**：AC ok/loss 双向去抖、VBUS 比例稳定去抖、爬坡去抖、就绪去抖、掉电去抖、故障重启去抖——覆盖所有状态切换。

### 2.5 电压判定方式
- **0824**：单门限（进 RUN 用 350V；RUN 中 OVP 420V / UVP 350V）。
- **0917**：READY 用**双门限范围** [359, 379]V 判定，掉电另有 345V 门限；OVP 设在 400V（全局前置）。
- 注：0824 的 `pfc_is_ready()` 额外二次校验 `bus ∈ [LLC_ENTRY_V(360), VBUS_OVP(420)]`，比 0917 单纯看状态更保守——**这条保留就好**。

### 2.6 故障恢复
- **0824**：`PFC_STATE_FAULT` 里直接 `pfc_disable()` 置 OFF，需外部重新 `pfc_enable()`（由上层 llc 状态机重拉，链路已确认通）。
- **0917**：FAULT 关断硬件后支持**自动重试**——冷却 `PFC_FAULT_RESTART_MS(1000ms)` 后清锁存回 IDLE 重新开始；或用户撤销使能直接回 IDLE。**不用人为重新下命令即可自愈**（前提是硬件故障已消失）。

### 2.7 硬件输出封装（⚠ 解决抖动根因）
- **0824**：`gpio_bit_set/reset` 直写，每次都落电平。
- **0917**：`pfc_hw_set_main()` 带 **`s_last` 缓存 + 首调用必落电平**，状态不变则不重复写 GPIO。
  
  ✅ 这正好消除之前 `llc_control` 评审里 **S3 的"同 tick PFC 断-开抖动"根因**——在 PFC 层做输出缓存最干净，比在 llc 层打补丁好。

### 2.8 OVP 检查位置
- **0824**：OVP 只在 RUN 态查（RAMP 阶段母线冲高查不到）。
- **0917**：OVP 在 `switch` **之前全局先判**，任何状态（含 RAMP）母线超 400V 立即 FAULT。

### 2.9 母线采样源
- **0824**：`g_adc_multi.bus_vol_v`（ADC0 DMA 连续扫描）。
- **0917**：`adc1_aux_read_channel(BUS_VOL_SAMPLE)`（ADC1 辅助轮询，独立通道）。
  
  → 修正我之前"0917 缺 BUS 采样"的说法：**0917 的 PFC 内部确实采了 BUS**，只是不走 ADC0 高速扫描、改走 ADC1 辅助读。功能上有 BUS 监控。

### 2.10 调试输出
- **0824**：无。
- **0917**：有 `#if 0` 包裹的 `debug_printf` 母线/AC 打印，联调时可一键开启。

## 3. 0824 相对 0917 的不足（按重要性）

| # | 不足 | 风险 | 对应 0917 方案 |
|---|---|---|---|
| D1 | 无 AC 输入检测 | 无 AC/AC 异常时照样合继电器，浪费且可能误动作 | AC ok/loss 去抖 |
| D2 | 继电器输出无缓存 | 上层反复 enable/disable 时继电器抖动脉冲（S3 根因） | `s_last` 缓存 |
| D3 | 无启动/爬坡/就绪分层延时 | 母线边界 350–360V 徘徊，is_ready 不稳定 | 三层时序 + 双门限 |
| D4 | 无上电 1.414 自检 | 无法区分"AC 没接"与"母线没建" | VBUS/VAC 比例自检 |
| D5 | FAULT 需手动重使能 | 联调中故障后要重发命令，效率低 | 冷却后自动重试 |
| D6 | OVP 不在全局前置 | RAMP 阶段母线冲高查不到 | switch 前全局 OVP |
| D7 | 无 AC 掉电显式处理 | AC 掉电只靠 UVP 间接反映，无区分 | AC loss 回 IDLE |
| D8 | 无调试打印 | 联调排错靠猜 | 可开关 printf |

## 4. 0824 更新方向（分阶段，适配"初版软硬联调"）

> 原则：不把 0917 的全部复杂度照搬，**只搬对初版联调最有价值的精华**；0824 的精简骨架本身没大问题。

### P0（建议必做，正确性 + 联调体验）
1. **加 AC 输入检测 + 双向去抖**（D1）：在 IDLE 阶段先判 AC RMS ∈ [85,265]V，去抖 200ms 才允许拉继电器。这是最大安全缺口。
2. **继电器输出加 `s_last` 缓存**（D2）：把 GPIO 直写改成"状态变化才落电平，首调用必落"，直接灭掉 S3 抖动。
3. **分层时序 + 双门限就绪**（D3）：`STARTUP_DELAY(约1s)` → 拉继电器 → `RAMP_DELAY(约100ms)` → 母线进 `[VBUS_MIN_START_V, VBUS_OVP_V]` 范围稳定 `READY_DELAY(约80ms)` → RUN。消除 350/360 边界抖动。
4. **上电 1.414 自检**（D4）：硬件未使能前验 `VBUS ≥ 1.414×VAC`（容差 5%，稳定 50ms），不通过不拉继电器。

### P1（健壮性，建议做）
5. **全局 OVP 前置**（D6）：把过压检查挪到 `switch` 之前，RAMP 阶段也能立即脱扣。
6. **FAULT 自动重试**（D5）：冷却 ~1s 后清锁存回 IDLE（保留现有"上层重拉"作为兜底，两者不冲突）。
7. **AC 掉电显式回 IDLE**（D7）：用 `pfc_ac_loss_debounced()` 区分"AC 掉电"与"PFC 故障 UVP"，都回 IDLE 但语义清晰。

### P2（可选，非阻断）
8. **可开关的 debug 打印**（D8）：仿 0917 加 `#if 0` 包裹的母线/AC 打印，联调排错直接开。
9. **核对门限对齐**：确认 `pfc_is_ready` 的 `LLC_ENTRY_V(360)` 与 llc 层 `LLC_ENTRY_V` 一致；0917 的 OVP=400 / 0824 的 OVP=420 窗口差异需按实际母线目标统一。

---

## 5. 保留 0824 的现有优点（不要动）
- ✅ `pfc_is_ready()` 的**二次电压校验**（state==RUN 且 bus∈[360,420]），比 0917 单纯看状态更保守。
- ✅ RUN 态 OVP/UVP 去抖已具备。
- ✅ 母线超时 3s 进 FAULT（`PFC_READY_TIMEOUT_MS`）已生效，防永久卡死。
- ✅ FAULT 即置 OFF、由上层 llc 重拉的恢复链路已确认通（初版够用）。

---

## 6. 一句话结论
0824 的 PFC 状态机**骨架正确、能跑联调**，但相比 0917 缺了 **AC 检测、上电自检、输出防抖、分层时序** 四块。最划算的更新是 **P0 的 4 条**（尤其 D1 AC 检测、D2 继电器缓存灭 S3 抖动），投入小、对初版联调体验和安全性的提升最大。
