# 0824 状态机「第一版软硬联调」适配评估

> 评估对象：`HW/src/llc_control.c`（主充电状态机）、`HW/src/pfc_control.c`（PFC 子状态机）、`App/src/serial_console.c`（联调驱动）、`App/src/main.c`（tick 编排）、`HW/src/protect.c`（故障/恢复）
> 评估目标：第一版软硬联调（bench，CAN 关闭）能否跑通、状态切换是否合理。**不要求完全功能，只验证联调可达、不卡死、可恢复。**
> 范围：温度 / 软件保护 / 风扇 相关通道仍按计划另评，本文仅确认它们"被注释"不影响状态机流转。

---

## 结论先行

**✅ 能适应第一版软硬联调。** 状态机驱动链路完整、状态切换自洽、无永久卡死分支、FAULT 可远程恢复。初版联调可直接用串口 SET/START/STOP/CLEAR 闭环操作。

唯一需要联调前确认的**非阻断**前置条件：电池端电压 ≥ 10V、PFC 母线稳态 ≥ 360V（否则会停在 PRECHARGE 超时）。这两条是模拟前端调参要求，不是状态机设计缺陷。

## 1. 驱动链路（bench 模式）

| 环节 | 实现 | 判定 |
|---|---|---|
| 使能/基准入口 | `serial_console.c` 的 SET/START/STOP/CLEAR 命令 | ✅ CAN 已注释（`main.c:256` 明文 "CAN intentionally uninitialized during first bench integration"），不影响 |
| SET 命令解析 | `sscanf(line,"SET %f %f",...)` | ✅ 已用 `sscanf`（非此前误报的 `scanf`），解析正常 |
| 安全看门狗 | 使能中 5s 无命令 → 自动 STOP（`serial_console.c:145`） | ✅ 防止联调遗忘导致长期带电 |
| 1kHz 编排 | `main.c` 每周期依次：`adc_multi_trigger/copy` → `protect_tick` → `pfc_tick` → `power_supervisor_tick` | ✅ 顺序正确，状态机读到新鲜 ADC 数据 |
| 初始化 | `adc_multi_init` / `pfc_init` / `protect_init` / `power_supervisor_init` 均在 `main.c` 调用 | ✅ |

**数据流无 stale 风险**：`adc_multi_copy()` 先把 DMA 缓冲搬入 `g_adc_multi.raw` → `adc_multi_sample_aux_1khz()` 转物理量 → 各 tick 用物理量判据（仅一帧 / 1ms 延迟，无碍）。

## 2. 状态切换合理性（联调视角）

```
            ┌─ vbat≥10V & enable ─┐
   STANDBY ─┤                      ▼
 (LED红)     └─ 否则 outputs_off ─┘    PRECHARGE ─ pfc_is_ready(母线≥360V) ─▶ CC
            ▲                          │  (合PFC继电器,等母线)              │  (合LLC_EN,下发基准)
            │                          └─ 3s超时 ─▶ FAULT                  │ 电压到ref-0.5V(1s) ─▶ CV
            │                                                          │  输出建立→合输出继电器(LED绿)
   FINISHED  │                                                          │ 电流≤1A持续30s ─▶ FINISHED
   (输断,     │                                                          ▼
    LED绿)    └──────────── 撤销enable ──────────────────────┘  CV(合继电器,等充满)
            ▲                                                          │
            └──────────── 撤销enable ───────────────────────────────┘
   FAULT(LED红, outputs_off) ── STOP + CLEAR 清锁存 ──▶ STANDBY
```

### 2.1 每个转换是否自洽

| 转换 | 条件 | 合理性（联调） |
|---|---|---|
| STANDBY→PRECHARGE | `enable && vbat≥10V` | ✅ 防空载误启动。**⚠ 注意**：联调若只接电子负载无 ≥10V，进不去（见 §4） |
| PRECHARGE→CC | `pfc_is_ready()`（母线 ≥360V 且 ≤420V） | ✅ 依赖 PFC 模拟侧把母线建到 ≥360V。母线建起门限 350V、进 LLC 360V、过压 420V，留 10V 余量，合理 |
| PRECHARGE→（超时） | 3s 内未 ready → `FAULT_PRECHARGE_TIMEOUT` | ✅ **已修**：原 A1「永久卡死」已加 3s 超时分支，不会无限等 |
| CC→CV | `vbat ≥ ref-0.5V` 持续 1s | ✅ 用 vbat 判据（旧评审 C4 标「该用 vout」，但联调能跑，非阻断） |
| CC→（合输出继电器） | `vout>10V` | ✅ 输出建立后才带载，安全 |
| CC→（超时） | `CHARGE_CC_TIMEOUT_MS=8h` | ✅ 已改回 8h（旧评审 B3 的 8s 调试值已修） |
| CV→FINISHED | `电流≤1A 且 电压≥ref-0.5V` 持续 30s | ✅ 满电流联调停在 CV 即可，无需真正充满 |
| 任意→FAULT | 软/硬件保护 | ✅ 即时 `outputs_off` + 红 LED（fail-safe 正确） |
| FAULT→STANDBY | `!enable && !latched && !hw_active` | ✅ **已修**：原 B2「不可恢复」已打通远程恢复（见 §3） |
| FINISHED→STANDBY | 撤销 enable | ✅ |

### 2.2 无死分支验证
- 所有「等待某条件」的状态（PRECHARGE / CC / CV）都有超时或 enable 撤销出口，**不存在无限等待无出口**的状态。
- `default` 分支把 TRICKLE/INVALID 兜底回 STANDBY，无 undefined 状态悬挂。
- `MAIN_STEP_INIT`（main.c 全局初值）无对应 case，走 default → STANDBY，无害；且 `power_supervisor_init` 已显式置 STANDBY。

## 3. FAULT 远程恢复（联调关键，确认已通）

**旧评审结论纠正**：此前《充电逻辑_保护_串口调试_评审》的 2.4「故障恢复断裂、永久锁死」——在当前代码版本**已不成立**，因为 `protect.c` 新增了异步清除机制：

1. 进 FAULT：`protect_set_fault()` 置 `s_fault_latched` + `g_charger_state=FAULT`（即时 fail-safe，✅）
2. 串口 `CLEAR` → `protect_clear_fault_async()`：发 10ms 清锁存脉冲（`HARD_FAULT_CLR`）
3. `protect_tick_1khz`：脉冲到时清 `s_fault_latched`，5ms 后校验硬件无故障则清 `g_fault`
4. `power_supervisor_tick` 顶部：`FAULT` 态检测 `!enable && !latched && !hw_active` → 回 `STANDBY`

→ 联调中进 FAULT 后，**STOP → CLEAR → 重新 SET → START** 即可恢复，无需断电复位。✅
（真硬件故障 `protect_fault_active_hw()` 仍为真时，CLEAR 校验不通过、不恢复——这是正确行为。）

## 4. 初版联调需注意的前置条件（非状态机缺陷，调参/接线要求）

| # | 条件 | 影响 | 对策 |
|---|---|---|---|
| ⚠1 | **电池端 vbat ≥ 10V** 才进 PRECHARGE | 只接电子负载（无 ≥10V 电压）会永远停在 STANDBY | 联调接真实电池，或在 bench 加「强制使能」标志 / 调低 `BATTERY_PRESENT_V` |
| ⚠2 | **PFC 母线稳态 ≥ 360V**（`LLC_ENTRY_V`）才进 CC | 若 PFC 模拟输出卡在 350~360V，PRECHARGE 等 3s 超时锁 FAULT | 把 PFC 母线目标调到 ≥365V（留余量）；初版若软启动慢，可临时调大 `PFC_READY_TIMEOUT_MS` |
| ⚠3 | **5s 看门狗**：使能中 5s 无命令自动 STOP | 想长时间保持充电需周期发 PING/命令 | 联调时定时 PING，或临时调大 `CONSOLE_WATCHDOG_MS` |
| ⚠4 | FINISHED 需电流 ≤1A 持续 30s | 满电流联调到不了 FINISHED，停在 CV | 正常，联调不要求真正充满 |
| ⚠5 | outputs_off 不复位 PWM 占空比（旧 C5） | 重新充电可能带旧占空比 | 每次 SET 立即 `apply_references` 下发新基准，已覆盖，无影响 |

## 6. 遗留的次要项（不影响初版联调，量产前清理）

- **C4**：CC→CV 判据用 `vbat` 而非 `vout`（逻辑可跑，物理上输出/电池端压差大时切换点略偏）。
- **C5**：`outputs_off()` 未复位 `CV_PWM/CC_PWM` 占空比（已被 SET 覆盖，无实际影响）。
- **A2**：CV 状态不切换基准（`apply_references` 只在 PRECHARGE→CC 调一次）。当前设计靠模拟 IC 双环自动 CC/CV，MCU 仅名义状态——注释与实现矛盾已就地标注，需确认是否符合预期。
- **门限注释滞后**：`llc_control.c:36` 仍写 OCP=30A，实际 24A，建议同步注释。

## 7. 一句话总结

状态机**结构上已能支撑第一版软硬联调**：串口驱动闭环、tick 编排与 ADC 数据流完整、PRECHARGE 有超时防卡死、FAULT 可远程恢复。联调前只需保证 **电池端 ≥10V**、**PFC 母线 ≥360V** 两条模拟前端条件，并注意 5s 看门狗。温度/软件保护/风扇不在本次范围，仍按计划另评。
