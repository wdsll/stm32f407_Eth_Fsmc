# OBC 状态机对比分析

> 参考项目: `CAN_LIMA48V10A` (48V 10A LLC充电器, 国民技术 N32G003)  
> 目标项目: `offline OBC/0824` (1.5kW OBC, GD32F303RE)  
> 分析日期: 2026-08-11

---

## 一、总体架构对比

| 对比维度 | CAN_LIMA48V10A (参考) | 0824 OBC (目标) | 差距 |
|----------|----------------------|-----------------|------|
| 状态机层数 | 5层 (主状态机 + 充电子状态机 + SCR关断 + AC保护 + 风扇检测) | 2层 (主状态机 + PFC子状态机) | 参考项目更完整 |
| 主状态数量 | 6个 (全部实现) | 9个 (仅4个实现) | **4个状态空壳** |
| 充电阶段 | CC/CV/TRI 全流程完善 | 只有 CC，CV/TRI/FINISHED 空壳 | **核心差距** |
| 故障恢复 | 有自动恢复 (告警→待机) | 无自动恢复 (需硬件复位) | **安全风险** |
| 时基 | 10ms (100Hz) | 1ms (1kHz) | 目标项目更快 |
| 通信 | CAN + UART 双通道 | 仅CAN | 参考更冗余 |

## 二、主状态机逐个状态对比

### 2.1 参考项目状态机

```
WAITING_BATPACK ──充电条件满足──► CHARGING ──充满/故障/拔电池──► SILICON_OFF
      ▲                              │                                  │
      │                              │                                  │
      └────────── 取走电池 ──────── WAITING_TAKE_AWAY ◄──── 关断完成 ──┘
      │
      └─── WARING(告警) ──立即──► WAITING_BATPACK (自动恢复)

      INVALID ──立即──► WAITING_BATPACK (兜底)
```

### 2.2 目标项目状态机

```
INIT ──自检──► STANDBY ──使能+电池存在──► PRECHARGE ──PFC就绪──► CC
                 ▲         ◄── 使能取消──               ◄── 使能取消──  │
                 │                                                        │
                 │   ◄──────────── CV/TRICKLE/FINISHED (default分支) ─────┘
                 │
                 └────────── 不可恢复 ────── FAULT ◄── 任何故障触发
                            (需硬件复位)
```

### 2.3 核心差距

| 参考项目状态 | 目标项目对应 | 实现情况 | 建议 |
|------------|-------------|---------|------|
| `WAITING_BATPACK` (待机+自检) | `STANDBY` | **缺失自检逻辑** | 参考自检:NTC开路检测、校准参数校验、PVD电源监测 |
| `CHARGING` (充电子状态机驱动) | `PRECHARGE`+`CC` | **缺失CV/涓流** | 参考实现 CC→CV→TRI→FINISHED 四级切换 |
| `SILICON_OFF` (安全断电序列) | 无 | **缺失** | 参考三步关断:关负载→延时300ms→关SCR |
| `WAITING_TAKE_AWAY` (等用户拔电池) | 无 | **缺失** | 参考LED指示+拔电池检测 |
| `WARING` (告警,可自动恢复) | `FAULT` | **设计不同** | 参考将告警/故障分开,告警可恢复,故障不可恢复 |
| `INVALID` (兜底) | `INVALID` | **目标有但无效** | 目标项目INVALID直接回STANDBY(无动作) |

## 三、充电子状态机详细对比

### 3.1 参考项目 (完整实现)

```
PRE(预充) ──电流大──► CCM(恒流) ──电流下降──► CVM(恒压) ──电流继续降──► TRI(涓流) ──完成──► FINISHED
   │                    │                       │                      │
   └──电流小──► TRI     └──超时7.7h──► FINISHED └──超时2.5h──► TRI   └──超时2.5h──► FINISHED
```

**各阶段详细行为:**

| 阶段 | 电压设定 | 电流设定 | 超时 | 风扇 | 保护动作 |
|------|---------|---------|------|------|---------|
| PRE | 浮充电压(低压试探) | 半额定电流 | 2s(BMS允许)/5s(盲充) | 开 | - |
| CCM | 目标充电电压(温度补偿后) | 额定电流(可降额) | 7.7h → FINISHED | 开 | 过温/风扇故障返回错误标志 |
| CVM | 目标充电电压 | 自动调节(自然下降) | 2.5h(温度自适应) → TRI | 开 | 同CCM |
| TRI | 浮充电压 | 0(经过CC+CV后)/额定(未经过) | 2.5h → FINISHED | 关 | MOS过温 → FINISHED |
| FINISHED | - | - | - | 关 | - |

**阶段切换电流阈值:**

| 切换 | 参考项目阈值 | 含义 |
|------|------------|------|
| CCM→CVM | 电流降至 ~26.4A (额定电流附近) | 进入恒压模式 |
| CCM/CVM→TRI | 电流降至 ~6A | 进入涓流 |
| 任何→FINISHED | 电流 < ~100mA 持续0.8-2s | 电池包拔出 |
| TRI→CCM(回来了) | 电流回升 > ~6.2A | 电池包重新大量吃电 |

### 3.2 目标项目 (仅有CC)

```
PRE(预充) ──PFC就绪──► CC(恒流) ──超时1.5s──► FAULT
```

| 阶段 | 行为 | 问题 |
|------|------|------|
| PRECHARGE | 闭合PFC继电器，等待PFC RUN + 母线≥360V | OK |
| CC | 设置CV_PWM/CC_PWM，LLC_EN=高，闭合输出继电器 | **只有恒流，没有阶段切换** |
| CV | 枚举有定义，switch无case → 落入default → outputs_off → STANDBY | **完全缺失** |
| TRI | 同上 | **完全缺失** |
| FINISHED | 同上 | **完全缺失** |

## 四、保护机制对比

### 4.1 保护类型覆盖

| 保护类型 | 参考项目 | 目标项目 | 差距 |
|---------|---------|---------|------|
| 输出过流 | 电流PWM限幅(软件闭环) | OCP >30A(硬件断开) | 目标缺乏逐周期限流 |
| 输出过压 | 电压PWM限幅 | OVP >80V(硬件断开) | OK |
| MOS过温 | **有**(>140°C关断, <110°C恢复) | **注释掉**(代码存在但未启用) | **严重缺失** |
| 环境过温 | **有**(>103°C关断, <85°C恢复) | **注释掉** | **严重缺失** |
| 变压器过温 | NTC开路检测 | **注释掉** | **缺失** |
| NTC开路/短路 | **有**(自检阶段检测) | 无 | **缺失** |
| 5V电源掉电 | **有**(PVD监测,充电中0.5s后停机) | **启动时检查**(ADC饱和→FAULT) | 参考更完善 |
| AC欠压降额 | **有**(<160V限流1A, <150V关断) | 无 | 目标无AC直接检测(PFC是模拟IC) |
| 风扇故障 | **有**(电流检测+堵转检测) | 无(硬件可能无风扇检测) | 按需 |
| CAN超时 | 隐含在BMS错误检测中 | **有**(3s超时→FAULT) | OK |
| 通信协议错误 | **有**(电压/容量/握手/类型/禁止) | 无(直接信任BMS数据) | 目标太简单 |

### 4.2 温度降额策略(参考项目有,目标项目无)

参考项目的多级降额:

```
正常 → 80%降额(环境温度分段) → 60%降额(严重高温) → 1A降额(AC欠压)
```

目标项目无任何温度相关逻辑,温度ADC通道均被注释。

### 4.3 故障恢复策略

| | 参考项目 | 目标项目 |
|--|---------|---------|
| 轻微故障 | WARING状态:关闭输出→立即回WAITING_BATPACK | 所有故障直接进FAULT |
| 严重故障 | 直接关断SCR→WAITING_TAKE_AWAY | 所有故障直接进FAULT |
| FAULT后恢复 | 无(同目标) | 需硬件复位 |
| 自动重试 | **有**(WARING自动清)| 无 |

## 五、参考项目的关键设计可借鉴点

### 5.1 待机自检逻辑

参考项目 `WAITING_BATPACK` 中包含完整自检:

```c
// 1. NTC温度传感器开路检测
// 2. 校准参数合理性检查 (at45 > at25 > atN10?)
// 3. PVD 5V电源监测
// 4. 电池包电压OK连续确认3次
// 5. BMS错误检测
// 6. 电池包已充满检测
```

目标项目 `STANDBY` 没有任何自检,直接等待CAN使能命令。

### 5.2 充电阶段切换时机

参考项目使用**电流阈值+连续去抖计数**判断阶段切换,防止误切换:

```
CCM → CVM: 电流 < 恒压进入阈值, 持续100拍(1s)
CCM/CVM → TRI: 电流 < 涓流阈值, 持续150拍(1.5s)
任何 → FINISHED: 电流 < 100mA, 持续80拍(0.8s)
```

### 5.3 温度补偿充电电压

参考项目每30分钟根据环境温度调整充电电压:

```
低温(-10~25°C): 每度增加 220 AD值
高温(25~45°C):  每度减少 440 AD值
```

### 5.4 安全断电序列(SCR关断状态机)

参考项目有专门的三步断电序列:

```
STEP_0: 关风扇, 电压/电流PWM归零
STEP_1: 延时300ms等待电容放电
STEP_2: 关闭SCR(输出开关), 恢复浮充电压PWM
```

目标项目直接 `outputs_off()` 同步断开所有继电器,没有延时等待。

### 5.5 边沿触发初始化

参考项目模式: 每个状态通过 `currentState != lastState` 检测首次进入,执行一次性初始化。

目标项目 `enter_state()` 有类似逻辑(记录进入时间戳),但仅用于超时判断,没有做状态进入的初始化动作。

### 5.6 错误标志编码

参考项目充电子状态机返回值用位编码:

```
高4位(0xF0): 错误标志 (过温/风扇/BMS)
低4位(0x0F): 当前充电阶段
```

主状态机通过位运算分离错误和阶段信息,主状态机和子状态机解耦。

## 八、总结

参考项目 `CAN_LIMA48V10A` 是一个**量产级**的充电器固件,状态机设计非常成熟:

1. **完整的充电路径**: PRE → CCM → CVM → TRI → FINISHED,每个阶段有超时保护
2. **丰富的保护机制**: 过温/风扇/AC输入/NTC/5V电源,覆盖全面
3. **精细的故障分级**: 告警(可恢复)vs 故障(不可恢复),兼顾安全和用户体验
4. **工程化的设计细节**: 电流阈值去抖、温度补偿、多级降额、安全断电序列

目标项目 `0824 OBC` 处于**早期开发阶段**(v0.2.2),状态机是一个骨架:

1. **充电流程不完整**: 只有CC,缺CV/TRI/FINISHED
2. **保护机制薄弱**: 过温保护全部注释,无NTC检测,无降额
3. **故障处理过于简单**: 所有故障进FAULT,无分级,无自动恢复
4. **架构合理但待填充**: PFC子状态机设计正确,主状态机枚举定义完整(9个状态),框架已经搭好,需要填充

**一句话总结**: 目标项目的架构框架是对的,但需要按 P0→P1→P2 优先级,参照参考项目的状态设计逐个填充状态行为和完整保护逻辑。
