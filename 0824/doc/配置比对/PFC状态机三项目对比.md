# PFC 状态机三项目对比：0824 vs 0917 vs CAN_LIMA48V10A

> 一个必须先说清的关键结论：
> **CAN_LIMA48V10A（48V10A 参考项目）并没有 MCU 侧的 PFC 状态机。** 它的 PFC 是板级硬件前级（疑似 NCP1654 类有源 PFC），MCU 完全不碰 PFC、也不采样母线（BUS/VBUS）电压。它的状态机是"充电状态机（PRE/CCM/CVM/TRI/FINISHED）+ 主状态机（待机/充电/SCR关断）"，唯一等价于"开关/继电器"的是**电池侧可控硅 SCR**。
>
> 因此三项目不能按"同构 PFC 状态机"硬凑对比，正确的对比维度是：
> **PFC 归谁管 / 母线是否可见 / AC 检测谁做 / 开关与断电时序 / 故障恢复哲学**。0824 与 0917 是同类架构（NCP1654 外置 + MCU 继电器/监控），CAN_LIMA 是"MCU 不碰 PFC"的对照组——它的价值在于**安全断电时序**和**软故障自动恢复哲学**，可作为 0824 的借鉴。

---

## 1. 三项目 PFC 维度总览表

| 维度 | **0824** | **0917** | **CAN_LIMA48V10A** |
|---|---|---|---|
| PFC 归谁控 | MCU 状态机 + NCP1654 | MCU 状态机 + NCP1654 | **纯硬件前级，MCU 零参与** |
| 母线(BUS)采样 | ✅ ADC0 DMA 扫 BUS | ✅ ADC1 辅助读 BUS | ❌ 无 BUS 通道 |
| PFC 状态机 | 4 态 OFF/RELAY_ON/RUN/FAULT | 4 态 IDLE/RAMP/READY/FAULT | ❌ 不存在（PFC 由硬件软启动） |
| AC 输入检测 | ❌ 无 | ✅ 85–265V 双向去抖 | 代码完整但**调用全注释停用** |
| 上电自检 | ❌ 无 | ✅ VBUS≈1.414×VAC | ❌ 无（仅 NTC/5V PVD/校准） |
| 开关器件 | AC 输入继电器 PC10 | 主继电器(合并脚) | 电池侧 SCR(PB3/PA5)，无机械继电器 |
| 安全断电时序 | ❌ 同 tick 同步断（无缓冲） | ❌ 同 tick 同步断（无缓冲） | ✅ **PWM→0 + ~300ms 延时 + 关断（缓冲防拉弧）** |
| OVP/UVP 位置 | 仅 RUN 态查 | switch 前全局前置 | AC 检测停用；活动仅 5V PVD + OTP + CV 限幅 |
| 故障恢复 | FAULT 手动重使能 | FAULT 冷却 1s 自动重试 | 软故障位标志 + 自动重试；**无看门狗、无锁存** |
| 看门狗 | （未确认，见备注） | （未确认） | ❌ IWDG 被注释，未启用 |
| 调试打印 | ❌ 无 | ✅ `#if 0` 可开 | ✅ USART2 周期帧 + 编译开关 |

> 备注：0824/0917 是否有看门狗需另查 main.c；本表只列已核实事实。CAN_LIMA 的"无看门狗"是其明确短板（评审需提示恢复或依赖硬件复位）。

## 2. 逐项展开

### 2.1 PFC 实现方（谁控 PFC）
- **0824 / 0917**：MCU 跑一个 PFC 状态机，负责"合 AC 继电器 → 等 NCP1654 建母线 → 监控 OVP/UVP → 故障脱扣"，PFC 电流环仍由 NCP1654 模拟完成。
- **CAN_LIMA48V10A**：MCU 对 PFC **零控制**。全局搜 `pfc/NCP1654/boost` 在应用代码零命中；母线建立完全由硬件前级软启动完成。固件里"预充"被**电池侧 PRE 软启动**取代（不是 AC 母线电容预充）。

### 2.2 母线电压可见性
- **0824**：`g_adc_multi.bus_vol_v`（ADC0 DMA 连续扫描）。
- **0917**：`adc1_aux_read_channel(BUS_VOL_SAMPLE)`（ADC1 辅助轮询，独立通道，非 ADC0 扫描）。
- **CAN_LIMA48V10A**：**无任何 BUS 通道**。ADC 单通道轮询只采 电流/输出电压/两路温度/风扇电流/电池电压。BMS 遥测也不含 BUS。即 PFC 健康度对 MCU 不可见，只能靠输出间接推断。

### 2.3 AC 输入检测
- **0824**：完全没有。合继电器前不判 AC。
- **0917**：`pfc_ac_ok_debounced()` 判 AC RMS ∈ [85,265]V，双向去抖；AC 掉电经 `pfc_ac_loss_debounced()` 回 IDLE。
- **CAN_LIMA48V10A**：`isOk_ACinput()` 写了**完整双门限 OVP/UVP + 1A 降额**（触发 150/285V、恢复 165/280V、欠压降额带 160–175V，去抖 `prtDelay>100`）——**但两处调用点全注释停用**。且历史代码用 `ADC_CHANNEL_CHARGING_VOLTAGE`（Vout）反推 AC，明显不合理，说明此功能从未正确接上。若硬件前级不带 MCU 侧 AC 保护，则交流异常只能靠硬件。

### 2.4 上电自检
- **0824**：无。
- **0917**：硬件未使能前做 `VBUS ≥ 1.414×VAC`（容差 5%，稳定 50ms），验证整流桥/输入正常后才拉继电器。
- **CAN_LIMA48V10A**：仅 NTC 开路 + MCU 自身 5V PVD + 校准值合法性；**无 VBUS≈1.414×VAC 自检**（因为它不采母线）。

### 2.5 开关器件与安全断电时序（⚠ 最大差异点）
- **0824 / 0917**：AC 输入继电器（机械），断电即 `gpio_bit_reset` / `pfc_outputs_off`，**同 tick 同步断 LLC_EN + 输出继电器 + PFC 继电器，无"先关功率再断开关"的缓冲时序**。
- **CAN_LIMA48V10A**：无机械继电器，唯一开关是电池侧 SCR。其 `SCROffStepProcess()` 做了标准的**安全断电缓冲序列**：
  ```
  SCR_OFF_STEP_0: 关风扇 → 两个 PWM 置 0（让 LLC 输出崩溃）→ 复位状态标志
  SCR_OFF_STEP_1: 延时 ~300ms 吸收电容余电
  SCR_OFF_FINISHED: 断言 SCR 关断 → 恢复浮充 PWM
  ```
  → 先关功率级、延时吸收余电、再断机械/半导体开关，**避免带载分断拉弧**。这正是 0824/0917 当前缺失、且之前 `llc_control` 评审 B1（安全断电无时序）所指出的痛点。

### 2.5.1 PFC 继电器关断时机对比（2026-08-27 补充）

> 2.5 讲"怎么断"（同 tick vs 缓冲序列），本节补充"**什么时候断**"的逐项目明细。结论一句话：**0824 被动关（仅命令/故障）、0917 主动关（离开运行态必先断 + AC/VBUS 异常去抖后主动断）、CAN_LIMA 无 MCU 侧 PFC 继电器**。

| 项目 | 合（闭合）时机 | 关（断开）时机 | 运行中 AC 掉电 | 运行中母线跌落 |
|---|---|---|---|---|
| **0824** | `pfc_enable()`：OFF→闭合，进 `RELAY_ON`（`pfc_control.c:39`） | ① 用户/系统 STOP → `pfc_disable()`；② 母线 3s 超时→`FAULT_PRECHARGE_TIMEOUT`→`PFC_STATE_FAULT` tick 内调 `pfc_disable()`；③ 充电故障/停机 → `outputs_force_off()`（`llc_control.c:116` 调 `pfc_disable`，LLC_EN/OUT_RELAY/PFC 三路同 tick 齐断）；④ 上电初始断 / CAL 校准固件硬锁 OFF | **保持闭合**（RUN 态空壳 `pfc_control.c:69-72`，无 AC 监控） | **保持闭合**（RUN 态无 VBUS 掉电监控） |
| **0917** | IDLE 内 **AC 去抖通过 + VBUS≈1.414×VAC 自检通过 + 启动延时到点**后 `pfc_hw_set_main(true)`（`:421-428`）；RAMP/READY 中若 `!hw_enabled` 会补拉（防单点掉） | ① 进 IDLE 必断（路径含 enable 撤销 / **AC 掉电去抖** `:437-440` / **VBUS 掉电去抖** `:495-503` / 故障恢复后）；② `pfc_handle_fault` **先立即断再进 FAULT**（VBUS_OVP 前置 `:384`、RAMP 超时）；③ FAULT tick 持续保断 | **去抖后主动断开**（回 IDLE） | **去抖后主动断开**（回 IDLE） |
| **CAN_LIMA48V10A** | 无（PFC 纯硬件前级，MCU 不碰继电器，也不采样母线） | 无 PFC 继电器；唯一开关为电池侧 SCR，关断走 `SCROffStepProcess()`（PWM→0 → ~300ms → 断言 SCR 关断，带缓冲） | —（AC 检测代码已注释停用） | —（MCU 无 BUS 通道，母线不可见） |

**差异本质**
- **0917 = 事件驱动主动断**：任何"离开运行态"的路径都先断继电器；AC/VBUS 异常经双向去抖主动触发断开，且故障时**先断硬件再进 FAULT 状态**（断电无 1ms 级延迟）。
- **0824 = 命令/故障被动断**：`RUN` 态为空壳，无 AC/VBUS 监控，继电器只在命令/故障两条路径才关；故障断继电器需等 `PFC_STATE_FAULT` 的 tick 执行（最长 1ms 延迟）。
- **CAN_LIMA**：无此概念，其唯一可借鉴点是 SCR 侧断电缓冲序列（2.5 已述）。

**对 0824 的直接含义**：与 0917 的核心差距 = **RUN 态缺 AC 输入检测 + VBUS 掉电监控**。对应更新方向：P0① AC 输入检测 + 双向去抖（合继电器前判 AC、运行中 AC 掉电主动断）、P1⑥ 全局 OVP 前置、P1⑤ 断电缓冲时序（借鉴 CAN_LIMA）。

### 2.6 过压/欠压保护（OVP/UVP）
- **0824**：OVP(420V)/UVP(350V) 仅在 RUN 态查（RAMP 阶段母线冲高查不到）。
- **0917**：OVP(400V) 在 `switch` **前全局前置**，任何状态都能立即脱扣。
- **CAN_LIMA48V10A**：AC OVP/UVP 在停用代码里；活动路径仅 MCU 5V PVD + 温度 OTP + CV 限幅（靠恒压闭环限幅，无独立母线 OVP 脱扣）。

### 2.7 故障恢复与看门狗
- **0824**：`PFC_STATE_FAULT` 直接 `pfc_disable()` 置 OFF，需外部重新 `pfc_enable()`（由上层 llc 重拉，链路已确认通）。
- **0917**：FAULT 关断后支持冷却 1s 自动重试（清锁存回 IDLE）或用户撤销使能回 IDLE。
- **CAN_LIMA48V10A**：**无独立 FAULT 状态机、无锁存**。故障以 `NNS_CHARGER_STATE_*` 位标志上报；OTP 温度回退后自动清标志继续充（软故障自动重试）、NTC 开路自动回待机下次重插再充。但 **IWDG 被注释未启用**，系统无 MCU 级生存兜底（评审需提示恢复或依赖硬件复位）。

### 2.8 调试打印
- **0824**：无。
- **0917**：`#if 0` 包裹的母线/AC 打印，联调一键开。
- **CAN_LIMA48V10A**：USART2 周期帧（每 0.5s 打印电流/电压/BAT/PVD/温度/状态），且有 `TIME_REDUCTION`(加速测试)/`FAN_CUR_TABLE` 等编译开关，联调排错最友好。

## 3. 对 0824 的更新方向（综合三项目精华）

0824 当前是"同类架构里最裸的版本"。更新优先级：

### P0（必做，正确性 + 联调体验）
1. **加 AC 输入检测 + 双向去抖**（借鉴 0917）：合继电器前先判 AC ∈ [85,265]V。最大安全缺口。
2. **继电器输出加 `s_last` 缓存**（借鉴 0917）：灭掉 `llc_control` 评审 S3 的"同 tick PFC 断-开抖动"根因。
3. **分层时序 + 双门限就绪**（借鉴 0917）：启动延时→拉继电器→爬坡延时→母线进范围稳定就绪；消除 350/360V 边界抖动。
4. **上电 1.414 自检**（借鉴 0917）：硬件未使能前验 `VBUS ≥ 1.414×VAC`。

### P1（健壮性）
5. **安全断电缓冲时序**（⭐ 借鉴 CAN_LIMA48V10A）：`outputs_off` 改为"先 PWM/LLC_EN→0 → 延时吸收余电 → 再断继电器"，避免带载分断拉弧。这是 0917 也没有、但参考项目做得最对的动作。
6. **全局 OVP 前置**（借鉴 0917）：OVP 提到 `switch` 前，RAMP 阶段也能脱扣。
7. **FAULT 自动重试**（借鉴 0917）：冷却后清锁存回 IDLE，减少手动重使能。
8. **软故障位标志 + 自动恢复哲学**（借鉴 CAN_LIMA）：过温/可逆故障用标志位自动重试而非硬锁死，提升联调效率（仅针对可逆故障，不可逆故障仍锁死）。

### P2（可选，非阻断）
9. **可开关调试打印**（借鉴 0917 + CAN_LIMA）：仿两者加 `#if 0` 包裹的母线/AC/状态周期打印 + 编译开关（如加速测试）。
10. **看门狗**：无论是否照搬 CAN_LIMA，都建议**启用 IWDG/WWDG**——CAN_LIMA 因注释掉看门狗而失去 MCU 级兜底，0824 不应重蹈。

---

## 4. 0824 应保留的现有优点
- ✅ `pfc_is_ready()` 二次电压校验（state==RUN 且 bus∈[360,420]），比 0917 单纯看状态更保守。
- ✅ RUN 态 OVP/UVP 去抖已具备。
- ✅ 母线 3s 超时进 FAULT，防永久卡死。
- ✅ FAULT 置 OFF + 上层 llc 重拉的恢复链路已确认通。

---

## 5. 一句话结论
- **0824 vs 0917**：同类架构，0824 缺 AC 检测、输出缓存、分层时序、上电自检、FAULT 重试——从 0917 搬这 4 条（P0）即可大幅提质。
- **CAN_LIMA48V10A**：不是"PFC 状态机"的可比对象，而是 **安全断电时序 + 软故障自动恢复** 的最佳参考；其"PWM→0 + 延时 + 关断"缓冲序列和位标志自动重试哲学，是 0824/0917 都缺的，值得补进 P1。
- **三者共同短板**：CAN_LIMA 无看门狗、0824/0917 断电无缓冲时序——这两点都应在 0824 更新里补齐。
