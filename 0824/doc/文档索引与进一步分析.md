## 二、进一步分析

### 2.1 评审覆盖度矩阵（源码模块 × 是否被评审）

| 源码模块 | 是否有专门评审 | 覆盖情况 |
|---|---|---|
| `main.c` | 部分 | 仅在健康检查/上板检查涉及；`protect_startup_check` 在保护报告提过，**无逐行评审** |
| `llc_control.c` | ✅ 强 | llc 评审 + enter 评估 + power_supervisor 评估 + 保护报告依赖分析 |
| `pfc_control.c` | ⚠ 弱 | 只有 PFC 状态机对比，**无逐行代码评审**（RUN 空壳 OVP 缺口未闭环） |
| `protect.c` | ✅ 强 | 保护模块逐行评审（08-24） |
| `adc_dma.c` | ⚠ 弱 | 仅在 ADC 对比里涉及配置；`protect.c` 的 `extern` 冗余被点名，**无代码评审** |
| `debug_printf.c` / `serial_console.c` | ✅ 强 | 串口模块逐行评审（08-24） |
| `pwm_llc.c` | ❌ 无 | 仅被 llc/保护报告顺带提到 `cv_pwm_set_duty`，**无专门评审** |
| `can_comm.c` | — | 已关闭（CAN disabled），暂不评审，合理 |
| `condition_held.h` | ❌ 无 | 新抽出的去抖模块，**无专门评审**（但逻辑简单、被两模块共用） |
| `gd32f30x_it.c` | ⚠ 弱 | 仅在保护报告 P0 点名"异常只死循环不关功率"，**无专门评审** |

**结论**：核心安全链路（protect / llc / 串口）覆盖到位；**明显缺口是 `pfc_control.c` 本体、`adc_dma.c`、`pwm_llc.c` 三个驱动层模块没有逐行评审**，而上板联调最先踩坑的往往就是驱动层（PWM 极性、ADC 标定、PFC 时序）。建议补这三份简短逐行评审。

### 2.4 跨文档待办汇总（全项目未关闭问题清单）

把各报告的 P0/P1/P2 抽取合并，按"安全兜底"聚类：

**P0 —— 安全兜底（上板前最该补）**
- CPU 异常处理器只死循环不关功率 → 需补 `fault_safe_off()`（保护报告）
- 独立看门狗 IWDG 未启用 → `main.c` 加 `fwdgt_config/enable` + 主循环 `reload`（保护报告）
- PFC 缺 AC 输入双门限检测 [180,264]V、上电自检缺 1.414 比例判定（PFC 对比 2.1/2.2）

**P1 —— 健壮性 / 硬件核对**
- 硬件故障信号是否直连 NCP4390 BKIN（无硬件直断则 MCU 死机=功率级失控）→ 需核对原理图（保护报告 + 早期原理图评审）
- 断电无缓冲时序 `outputs_force_off` 三路齐断（B1）→ 先关 LLC→泄放→再断继电器（保护报告）
- PFC 启动时序抗抖动、母线采样源、OVP 检查位置（PFC 对比 2.7/2.9/2.8）
- `enter_state` 缺幂等守卫、故障未统一走 enter（enter 评估 P0/P1）

**P2 —— 边界 / 整洁**
- 串口：CLEAR 死注释未删、SET 上限 80V（应≤60V）、看门狗不 pet、RX 无 FIFO（串口报告）
- 保护：OVP 64→60~62V、extern 冗余、outputs_force_off 旧 C5 注释过时（保护报告）
- PFC：RUN 空壳补 OVP（PFC 对比）

**已落实（跨文档确认）**
- 上电清锁存（main.c `protect_startup_check`）—— 旧 P2-④ ✓
- 去抖重构为 `condition_held.h` —— 重构方向正确 ✓
- 保护从简（clear 脉冲简化、枚举占位）✓

**洞察**：所有 P0 都落在"安全兜底"层（异常/看门狗/AC 检测），不是功能缺失而是**失效安全（fail-safe）缺口**——初版联调用稳压源+电子负载模拟时尚可接受，但一旦接真电池，这些是必须补的。

### 2.5 文档治理建议

1. **命名不统一**：有的带日期、有的不带；有的叫"评审"、有的叫"评估"、"对比"、"检查"。建议统一为 `YYYYMMDD_模块_类型.md`（如 `20260824_保护模块_评审.md`），一眼可排序、可溯源。
2. **缺索引**：17 份 md 之间靠文件名弱关联，**缺一份 `README/索引` 标注每份的状态（基线/对标/收尾/已刷新）与结论一句话**。本文件即尝试补此空缺。
3. **版本挂钩**：早期发生过"旧 doc 过期（CC/CV 超时 8s vs 实际 8h）"的误报。建议在每份评审头部固定标注「基于代码日期 / commit / 文件清单」，评审时先 `git diff` 确认未变再引用。
4. **空目录 `0ld/`**：建议删除，或改为明确的 `archive/` 并写清归档规则（如"被刷新取代的旧版移入"）。
5. **收敛重复主题**：状态机 4 份对比 → 1 份汇总；保护 3 份 → 1 份带版本评审。
