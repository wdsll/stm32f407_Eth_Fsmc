# 0824 OBC 项目 基础外设配置评审（聚焦：定时器 / PWM / ADC / 串口 / 时钟树）

> 评审目标：**不要求功能完善，只要求初版软硬联调不会因为外设配置错误而跑不起来**。
> 评审日期：2026-08-18。结论均基于亲读源码 + 固件库宏定义核实。
> 范围：系统时钟、PWM(TIMER0/1)、ADC+DMA、USART2 调试串口、TIMER3 监控节拍、SysTick、GPIO 引脚复用、NVIC 优先级。
> 明确未评：温度/软件保护/风扇（按之前约定）、CAN 协议层（仅看引脚配置，协议帧格式属另一文档 S1）。

---

## 〇、一句话结论

**有一个会直接让初版联调"开不了串口"的配置级致命 bug：USART2 缺少 PB10/PB11 全重映射。** 其余外设配置（时钟树、PWM、ADC 采样、定时器、DMA、引脚、中断优先级）核对后基本正确，仅 ADC 时钟 15MHz 略超典型 14MHz 上限需确认。

---

## 一、时钟树核实（决定一切外设时钟）

来源 `HW/src/RCU.c:25-47`：
- PLL：`RCU_PLLSRC_HXTAL_IRC48M` + `RCU_PLL_MUL30`，且 `RCU_CFG0_PREDV0` 置位（HXTAL 先 ÷2）。
  - 若外部晶振 8MHz：8MHz ÷ 2 × 30 = **120MHz** ✓（与 `main.h:24` `SYSTEM_CLOCK_HZ=120MHz` 一致）
- AHB = `DIV1` → **120MHz**
- APB1 = `DIV2` → **60MHz**
- APB2 = `DIV1` → **120MHz**

推论（GD32 定时器规则：APB prescaler=1 时定时器时钟=PCLK；否则=2×PCLK）：
- TIMER0（CV_PWM，在 APB2，prescaler=1）→ **120MHz** ✓（`pwm_llc.c:46` `rcu_clock_freq_get(CK_APB2)`）
- TIMER1 / TIMER3（在 APB1，prescaler=2）→ 2×60 = **120MHz** ✓（`pwm_llc.c:31-33` `timer1_clk_hz()` 的 ×2 逻辑正确）
- ADC 时钟 = `RCU_CKADC_CKAPB2_DIV8` = 120/8 = **15MHz**（见第三节问题 2）

时钟树本身正确，系统跑 120MHz 没问题。

## 二、严重问题（会导致联调立刻卡住）

### 🔴 P1 USART2 未做 PB10/PB11 全重映射 —— 调试串口完全不出波形
**位置**：`App/src/debug_printf.c:13-30`（缺重映射调用）；`App/include/main.h:239-247`（引脚定义 PB10/PB11）

- `main.h` 明确把调试串口定义为 `USART2` + `PB10(TXD)` / `PB11(RXD)`。
- 但 GD32F303 的 USART2 **默认引脚是 PA2/PA3**；映射到 PB10/PB11 必须做 **全重映射** `GPIO_USART2_FULL_REMAP`（固件库 `gd32f30x_gpio.h:398` 已确认该宏存在，值为 `0x00140030`）。
- `debug_printf_init` 里只做了 `rcu_periph_clock_enable(RCU_AF)`（重映射的前置条件已满足），**却从未调用 `gpio_pin_remap_config(GPIO_USART2_FULL_REMAP, ENABLE)`**。
- 全工程 grep `gpio_pin_remap_config` / `REMAP`：**仅在固件库内部出现，应用代码零调用**。

**后果**：
1. USART2_TX 实际出现在 **PA2**，而非板子调试座的 PB10 → PC 端串口助手收不到任何字符（"开串口是黑的"），初版联调第一步就卡。
2. 潜伏引脚冲突：默认 USART2_RX=PA3，而 PA3 被 `adc_dma.c` 配成 `BUS_VOL_SENSE` 的 ADC 模拟输入（`GPIO_MODE_AIN`）。不做重映射时 PA3 同时被 USART2_RX 与 ADC 抢占，母线电压采样也会被干扰。

**修复（一行）**：在 `debug_printf_init` 中、`rcu_periph_clock_enable(RCU_AF)` 之后加：
```c
gpio_pin_remap_config(GPIO_USART2_FULL_REMAP, ENABLE);   /* USART2 → PB10/PB11 */
```
> 注意：`Use MicroLIB` 也必须在 Options→Target 勾选（代码注释已提示），否则 `printf`/`vsnprintf` 不输出。

## 三、主要问题（建议量产前确认/修正）

### 🟠 P2 ADC 时钟 15MHz，踩在典型 14MHz 上限
**位置**：`HW/src/adc_dma.c:27` `rcu_adc_clock_config(RCU_CKADC_CKAPB2_DIV8)`

- APB2=120MHz，÷8 = **15MHz**。
- GD32F30x 系列 ADC 时钟（ADCCLK）**典型上限 14MHz**（以 GD32F303RET6 数据手册为准，请核对你手上的器件手册）。15MHz 超出约 7%，属**超规格运行**：常温下大概率能采样，但高温/边界条件下精度与稳定性无保证。
- 对"初版联调"影响：大概率能跑、能看到数值，但**不是合规配置**。
- 修复：改为 `RCU_CKADC_CKAPB2_DIV12` → 10MHz，稳妥落在规格内（代价：单通道采样时间略变长，5 通道扫描总时长需重新核算，仍远小于 200ms 窗口，不影响 5kHz 节拍）。

### ⚪ P3（顺手）SysTick 依赖 SystemCoreClock 已更新
**位置**：`App/src/main.c:66-81` `systick_1ms_init`

- `reload = SystemCoreClock / 1000 - 1`，且先调用 `SystemCoreClockUpdate()`（line 68）。
- 只要 `SystemCoreClock` 被 `system_gd32f30x.c` 正确设为 120MHz（PLL×30 路径），reload=119999，1ms 节拍正确。
- 已核实 `system_gd32f30x.c` 有对应 120MHz 配置路径，且 map 文件显示 `SystemCoreClock` 被引用。**基本无风险**，仅提醒：若以后改时钟树，务必同步 `SystemCoreClock`，否则 SysTick 节拍漂移会牵连所有 `elapsed_reached` 超时判定。
