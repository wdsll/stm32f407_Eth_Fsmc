# 0824 保护模块「初版上板、从简」评估

> 评估对象：`HW/src/protect.c` + `HW/include/protect.h`（当前 13:43 版本）
> 评估视角：**第一版软硬联调，保护不做复杂设计**，只保"会炸机"的硬保护，其余后移
> 结论：当前 protect.c 已接近"初版最小集"，基本符合从简原则；再砍 2 处、补 1 处轻量去抖即可上板

---

## 1. 当前保护清单 vs 初版最小集对照

| 保护项 | 当前状态 | 初版是否必要 | 处置 |
|---|---|---|---|
| LLC_FAULT_CHECK 硬件锁存轮询 | ✅ 生效（D触发器，低=故障） | **必须** | 留 |
| VOUT_OVP（输出过压 64V） | ✅ 生效 | **必须**（炸电池/后级） | 留 |
| IOUT_OCP（过流 24A，软件后备） | ✅ 生效 | **必须**（过流兜底） | 留 |
| 过温 4 路（PFC/LLC MOS/变压器/外壳） | ⚠ 全注释 | 暂不需要 | **保持注释**（你要求先不管） |
| 母线 BUS_OVP/UVP（MCU 软件判） | ⚠ protect_tick 未查；pfc RUN 空壳 | 暂不需要 | 保持不查，靠硬件前级 + LLC_FAULT_CHECK 兜底 |
| AC 输入异常 | ⚠ 不在此模块（pfc 层） | 暂不需要 | 保持 |
| 降额阶梯 / 温度补偿 | ⚠ 未实现 | 暂不需要 | 保持 |

**判断**：当前已符合"只保会炸机的"原则，没有过度设计。过温/母线/降额全部后移 —— 方向对。

## 2. 可进一步从简（2 处，初版非必须）

### 2.1 clear 脉冲的 async 三阶段状态机可不用
`protect.c:55-110` 的 `protect_clear_fault_async` + `s_clear_pulse_active` + `s_clear_verify_pending`
是一套"不阻塞 1kHz 调度"的运行时清锁状态机（set→等10ms→reset→等5ms→verify）。

初版上板，清锁只在两个地方发生：**启动预检一次** + **串口 CLEAR 命令一次**，都不在高频循环里。
→ 直接用已实现的**阻塞版 `protect_clear_fault()`**（`:70-81`，`delay_ms` 脉冲）足够，async 那套可删。

**注意**：这是"可选简化"，不是 bug。async 版无害且更优雅，留着也行；若想初版最干净，删掉它只留阻塞版。

### 2.2 fault_type_t 枚举里的"未来项"保持占位即可
`main.h:301-310` 的 `FAULT_BUS_OVP / FAULT_OVER_TEMP_* / FAULT_CAN_TIMEOUT / FAULT_CHARGE_TIMEOUT` 等当前不被触发（对应保护未接）。
→ 初版**保留枚举定义但不用**，不要为了"看起来完整"去接这些保护。等硬件稳定、二审保护时再逐个激活。

## 3. 初版反而建议补的 1 处（轻量、防误锁）

### 3.1 OVP / OCP 加 10~50ms 持续判定再去锁
当前 `protect_tick_1khz`：
```c
if (g_adc_multi.vout_v > VOUT_OVP_V) { protect_set_fault(FAULT_OVP); return; }   // 一拍就锁
if (g_adc_multi.iout_a > IOUT_OCP_A) { protect_set_fault(FAULT_OCP); return; }   // 一拍就锁
```
**没有任何去抖**。初版上板第一怕：上电暂态、继电器合瞬间、ADC 毛刺 → 一拍误锁死，表现成"一使能就 FAULT，反复发 CLEAR 才偶尔能充"，拖慢联调。

这**不是"变复杂"，是让初版更稳、反而更简单**：
```c
#define PROT_DEBOUNCE_MS (30U)
static uint32_t s_ovp_ms=0, s_ocp_ms=0;
/* OVP */
if (g_adc_multi.vout_v > VOUT_OVP_V) { if(elapsed_reached(s_ovp_ms,PROT_DEBOUNCE_MS)){protect_set_fault(FAULT_OVP);return;} }
else s_ovp_ms=g_ms;
/* OCP 同理 */
```
30ms 持续超阈才锁，毛刺直接滤掉。**建议初版就加**，代价极低。

## 4. 已确认正常（不再赘述）
- 🟢 `protect.c:15` 已 `#include "llc_control.h"` → 上一轮 P0「跨模块隐式声明」隐患已关闭，armclang v6 可编过
- 🟢 `IOUT_OCP_A=24A` 在 ADC 满量程内，软件后备过流**生效**（非死代码）
- 🟢 `protect_set_fault` → `power_supervisor_enter_fault` 收敛链路通，FAULT 可远程 CLEAR 恢复
- 🟢 硬件锁存 `LLC_FAULT_CHECK` 是真正的 fail-safe 兜底（即使 MCU 卡死，硬件故障也能靠 D触发器锁存断电）

## 5. 上板前保护最小动作清单
1. **保留**：LLC_FAULT_CHECK 轮询 + VOUT_OVP + IOUT_OCP（三项硬保护）
2. **保持注释**：过温 4 路、母线软件 OVP/UVP（初版靠硬件前级兜底）
3. **建议补**：OVP/OCP 各加 30ms 去抖（防上电毛刺误锁）
4. **可选简化**：删 async clear 状态机，只用阻塞版 `protect_clear_fault`
5. **别动**：fault_type_t 枚举保持现有占位（未接的保护不急着连）

> 一句话：当前保护**不过度**，初版可直接上板；唯一建议补的是 OVP/OCP 的 30ms 去抖，避免采样毛刺把联调卡在反复锁死里。
