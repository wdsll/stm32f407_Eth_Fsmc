## 〇、整体结论（v2）

架构与 fail-safe 思路正确（保护即时断三路、非阻塞串口、ADC DMA+FTF 同步、FAULT 顶部收敛）。v1 列出的阻断级问题中，**3.1/3.2 已解决**，**2.4 的"永久锁死"已不成立**。当前真正要盯的三件事：

1. **母线过压保护仍缺失**（P2，唯一未动的架构级缺口）：`pfc_tick` RUN 态空壳，`VBUS_OVP_V=420` 从未作为故障触发；0917 已实现，0824 建议移植。
2. **过温保护数据源全断**（T1/2.2，维持）：ADC 只扫 5/10 通道，4 路 NTC + FAN_CS 不在序列，protect 过温整段注释。
3. **OCP 贴边**（2.1 重判）：24A 判据距 ADC 满量程 24.8A 仅 0.8A，标定误差可直接吞掉保护裕度，需"饱和即故障"兜底。

## 一、充电逻辑

### 1.1 PFC 子状态机（pfc_control.c，100 行，v2 重核）

状态：`OFF → RELAY_ON → RUN → FAULT`。驱动：`pfc_tick_1khz()`（1kHz）。

| 位置 | 行为 | v2 评价 |
|---|---|---|
| `:35-43` `pfc_enable` | 仅 OFF 态响应，闭合 PFC 继电器，进 RELAY_ON | ✅ |
| `:57-67` RELAY_ON | `bus≥350V`→RUN；**新增** `PFC_READY_TIMEOUT_MS`(3s) 超时→`FAULT_PRECHARGE_TIMEOUT`+进 FAULT | ✅ v1 之后新增的超时，防 RELAY_ON 永久等待 |
| `:69-72` RUN | 空壳（仅注释"加入OVP的保护"） | ⚠ P2 维持：母线 OVP 缺失 |
| `:74-76` PFC_FAULT | 每 tick `pfc_disable()` | 🟡 v1"无恢复"表述修正：`pfc_disable()`(:45-49) **无条件置 OFF**，PFC_FAULT 实际只停留 1 tick，状态机自愈回 OFF；真正的锁存在上层 `g_charger_state/latched`（由 CLEAR 链路解开）。PFC 子机无独立恢复需求 |
| `:82-90` `pfc_is_ready` | `RUN ∧ AC∈[180,264] ∧ bus∈[360,420]` 三重门 | ⚠ P3 维持+扩展（见下） |

**P2 — 母线过压（VBUS_OVP）缺失（严重，唯一架构级遗留）**
`protect.c` 无 BUS_OVP 轮询；`VBUS_OVP_V=420` 仅被 `pfc_is_ready:87` 用作 is_ready 上限判据——母线真冲到 420V 以上时，效果只是 `pfc_is_ready()=false`（PRECHARGE 卡 3s 报"超时"），**不是即时 OVP 故障**。RUN 态母线过压完全裸奔（NCP1654 自身 OVP 是唯一防线）。**修复**：在 `pfc_tick` 的 RUN 态顶部加 `if (bus_vol_v >= VBUS_OVP_V) { protect_set_fault(FAULT_BUS_OVP); }`（0917 版本已在 tick 顶部实现 400V 全状态覆盖，直接移植）。

**P3 — pfc_is_ready 三重门的两个边界（维持+扩展）**
- 死区：母线 304~360V 之间 PFC 不报故障但 is_ready 恒假 → llc PRECHARGE 卡 3s → `FAULT_PRECHARGE_TIMEOUT`。v1 说"永久卡死"不准确——A1 超时补丁落地后是"3s 报超时"，但故障码掩盖了真实原因（见 1.3 N6）。
- **AC 下限 180V 拒绝 165V（新关注）**：PFC 板实测 165V/1300W 可运行（受交流源 8.4A 限流）。若业务需要 165V 输入能力，`PFC_AC_INPUT_MIN_V`（main.h:80）需下调（如 150V）；若 180V 是有意的设计门槛，保持并在文档注明"165V 仅 PFC 单板调试，整机不支持"。

### 1.2 PWM 设定值生成（pwm_llc.c）

CV_PWM=TIMER0(PA8)、CC_PWM=TIMER1(PA0)，经 RC 滤波变成模拟 IC 基准。

**亮点（v2 维持）**：时钟处理正确（APB1 ×2 规则）；`f_clampf` 全程限幅；影子寄存器更新无毛刺；`outputs_force_off` 里 PWM 置 `PWM_DUTY_SAFE`（C5 已修，重新充电必从 0 起步）。

**P4 — 软启动/斜率限幅从未实现（维持，严重度降级）**
`main.h:191` `PWM_DUTY_SLEW=0.002` 与 `:193-200` `LLC_SOFTSTART_*` 宏**全工程零引用**（2026-09-03 grep 确认）。但实际风险比 v1 评估的低：① 基准只在 `enter_state(CC)` 下发一次（C3 修复后 STANDBY 无每 tick 写 PWM）；② `power_supervisor_set_references` 在线改基准仅在 STOP 态可做（串口 SET 运行中拒绝）；③ 模拟 IC 自带软启。**降级理由**：阶跃仅发生在"从 0 到 SET 值"这一步，且被 PWM 占空比钳位与模拟 IC 软启缓冲。**维持建议**：接真电池前用示波器看一次基准爬坡；若过冲明显，再落斜率限幅（用 `PWM_DUTY_SLEW` 在 `apply_references` 里做逐步逼近），否则删宏。

### 1.3 充电状态机联动（llc_control.c，370 行——详评审 v3）

- **A1 超时**：PRECHARGE 3s 超时 ✓（且 pfc 层 RELAY_ON 也有同款 3s 超时，双层冗余，pfc 层先触发）。
- **B2 恢复语义**（v2 重写）：FAULT 恢复 = STOP→CLEAR→下一 tick 自动回 STANDBY；`!protect_fault_active_hw()` 项因 protect.c 硬编码恒真。**无人干预的自恢复不存在（人工确认语义）**——与 v1"断裂"结论不同，链路是通的。
- **N6 预充故障码无诊断性**：三重门任一不满足+3s 都报 `FAULT_PRECHARGE_TIMEOUT`——AC 越限、母线建不起、母线过压（>420V 反使 vbus_ok=false）共用一个码。建议超时分支按 `ac_vol_v`/`bus_vol_v` 实测值细分故障码（补丁见 llc_control 评审 v3 补丁 B）。
- **C1 完成判据风险（v2 新增强调）**：`iout_a<=1A` 在电流通道未标定时可能恒真 → 提前误判 FINISHED。接真电池前必须完成电流点校。

### 1.4 ADC 采样通道—— 温度/风扇仍没扫（T1 维持）

`adc_dma.c:49-52` 扫描序列 5 路：AC/BUS/VOUT/I_SENSE/VBT。`main.h` 定义 10 通道（含 4 路 NTC：T_CASE=PA4、T_PFC=PA7、T_TR=PC4、T_LLC=PB1；FAN_CS=PA2），**均不在序列**，`ADC_CHANNEL_QTY=5`（main.h:154）。

后果链（v2 维持）：`g_adc_multi.t_*` 永为 0 → `ntc_raw_to_temp_c()` 整段 `#if 0`（adc_dma.c:189-200）→ protect 过温 4 路整段注释（protect.c:114-118）→ `TEMP_DERATING_*/TEMP_SHUTDOWN_C` 零引用 → **过温保护物理不可能生效**。1.5kW 产品量产前必须补全（恢复时四处同步：ch_list + ADC_CHANNEL_QTY + t_* 字段 + ntc 函数 + protect 解注释）。

其余 ADC 要点（下溢补丁落地、AC RMS 数学、采样率风险）见 `ADC模块评审_逐行注释.md` v3。

## 二、保护部分（protect.c，127 行——详评审 v3）

### 2.1 软件 OCP（v2 重判：死代码问题消失，新风险是贴边）
v1 语境（OCP=30A > 满量程 24.8A，恒假死代码）**已失效**：0824 现值 `IOUT_OCP_A=24A`（main.h:92），落入可测区间，判据有效 ✓。**新风险**：24A 距满量程 24.8A 仅 0.8A，V_offset/增益 ±2% 标定误差即 ±0.5A@20A，判据可能够不到。建议：① 电流点校；② protect 加 `isense_raw >= 4000` 饱和即 FAULT_OCP 兜底。

### 2.2 过温保护缺失（维持 🔴）
见 1.4。数据源不解决，解注释无意义。

### 2.3 母线过压缺失（维持 🔴）
见 P2。这是当前保护体系唯一未动的架构级缺口。

### 2.4 故障恢复路径（v2 重写：链路已通，语义=人工确认）
v1"CLEAR 清了硬件锁存但 g_charger_state 永久卡 FAULT"的结论**已被推翻**——llc_control FAULT 顶部有恢复分支（`:287-291`）。当前完整链路：
```
STOP（en=false）→ CLEAR（protect_clear_fault：脉冲清 D 触发器 + 清 latched + g_fault=NONE）
→ 下一 tick：!en && !latched（active_hw 恒真项）→ enter_state(STANDBY) ✓
```
两个 v2 级注意点：
- **active_hw 硬编码恒假**（protect.c `#if 1`）使 CLEAR 的"硬件未解除拒绝清"守卫失效——CLEAR 现在无条件清软锁存；若 D 触发器真在锁存态，MCU 显示 fault=NONE 但硬件仍在故障。因功率已断（outputs_force_off）安全可控，但"恢复 active_hw 轮询"时必须联动恢复串口 CLEAR 拒绝分支（serial_console.c:236-239）与 START 三重门——绑定同一提交。
- **无人干预自恢复不存在**（latched 只能被 CLEAR 清）：对 OVP/OCP 类故障是合理的人工确认语义；若将来要时序类故障（如 PRECHARGE_TIMEOUT）自恢复，需新增接口区分故障类别。

### 2.5 OVP 阈值（v2 重判：合理）
`VOUT_OVP_V=94V`（main.h:91）对 20串 Li-ion 满电 ≈84V 约 12% 裕量——v1"80V 对 58V 目标偏宽松"的语境作废，现值合理，**无需调整**。

### 2.6 亮点（保护，v2 维持+新增）
- `protect_set_fault` 即时断三路再锁存，fail-safe 正确；LLC_EN 极性已随 `llc_disable()`（低有效拉高）更新。
- FAULT 态 `protect_tick` 早退并复位去抖，防重复触发。
- OVP/OCP 30ms 去抖（condition_held 重构共用组件）。
- 启动自检 `protect_startup_check` 顺序正确（硬件故障→失败；锁存→先清）。

`serial_console.c:192` 现为 `sscanf(line,"SET %f %f",...)`。v1 阻断项闭环。

### 3.2 ~~UART 联调 START 触发 CAN 超时故障~~ → ✅ 随 CAN 禁用消失

## 五、修复优先级建议（v2）

```
P0（接真电池/上功率前）：
  1. 2.1  电流点校 + OCP 饱和兜底（isense_raw>=4000）—— OCP 有效性前提

  4. T1   ADC 温度通道 + NTC 换算 + 过温解注释（四处同步）
  5. P3   预充故障细分（按 AC/BUS 实测值分流故障码）；确认 AC 下限 180/165 业务口径
  6. P4   基准阶跃 bench 确认；明显过冲再落 PWM_DUTY_SLEW，否则删宏

P2（清理）：
  7. 过时注释批量清理（5s/64V/8s/3s/OCP=30A/C5 死注释等，见各专项评审清单）
  8. print_status_test 死代码、死宏（VBUS_TARGET_V/PWM_DUTY_SLEW/LLC_SOFTSTART_*/V3V3_*/TEMP_DERATING_*）
  9. COMMISSIONING_USE_UART 做成真正的编译开关；CAN 集成时带 g_can_active 门控回归
```

> v2 总结：v1 的三大阻断项（scanf/CAN 超时/恢复断裂）全部闭环，串口联调通道已实测可用。当前重心转向**保护完备性**（母线 OVP 移植、OCP 兜底、过温数据源）——这三项补齐前，建议只在有人盯守的台架环境上功率。
