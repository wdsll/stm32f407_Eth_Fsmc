## 二、问题清单（v4）

### 🟠 P2（建议本轮迭代处理）

**1. `#if 0` 块内接口名笔误——将来启用即编译失败**
`:138` 写的是 `power_supervisor_voltage_reference0()`（多了个 `0`），llc_control.h:23 的正式接口是 `power_supervisor_voltage_reference()`。当前被 `#if 0` 屏蔽不报错，但任何人打开就会编译不过。
**建议**：该函数已被 `print_status(include_raw=true)`（:149-169，含 RAW 行）完全取代，直接**删除 :128-148 整块**，不留僵尸代码。

**2. START 的"参考已设"判据与 SET 下限脱节（两套魔数）**
```c
:216  else if((power_supervisor_voltage_reference() < 10.0f)||(power_supervisor_current_reference() <= 0))
```
SET 下限已是 **32.3V**，因此 `< 10.0f` 在纯串口路径下不可达（SET 拦在前面），属"看起来在把关、实际永远不触发"的判据；但将来 CAN/诊断口接入时，若写入 15V 参考，START 会放行一个**低于硬件可调下限**的设定值。
**建议**改用同一宏，消除魔数：
```c
else if (power_supervisor_voltage_reference() < LLC_CV_REFERENCE_MIN_V ||
         power_supervisor_current_reference() <= LLC_CC_REFERENCE_MIN_A)
```

**3. STATUS 帧诊断字段不足（针对当前联调痛点）**
现有字段：`state / fault / en / pfc_state / ref / ac / bus / out / bat / i`。最近排查母线爬坡、PRECHARGE 卡死、看门狗自停时全靠 bus 值反推。建议补四个字段（成本极低）：
- `lock=<latched><hw>`：`protect_fault_latched()` / `protect_fault_active_hw()`——一眼看出锁存有没有清；
- `relay=<llc><out>`：读回 `LLC_EN`/`OUT_RELAY` 的 **GPIO 实际电平**（非命令状态）——配合 wf4(2) 引脚宏修正后的回归验证；
- `drop=<1k><5k>`：`s_tick_drop_count` / `s_adc_monitor_tick_drop_count`（需 main.c 暴露只读接口）——判断主循环是否被拖慢；
- `boost=<V>`：`bus - ac×1.414`（PFC 抬升量）——直接判断 PFC 是否真起环（见母线 320→390 评审结论）。
> 帧长 ~90B→~130B，115200、1s 一帧无压力（发送环形缓冲 1KB）。

**4. 接收循环无字符数上限**
```c
:263  while (debug_getchar(&ch)) { ... }
```
上位机持续灌数据或 RX 线受扰时，本轮主循环会一直在此排空。虽然 1kHz 控制任务先于 `serial_console_task()` 执行（不会丢控制节拍），但会推迟下一圈开始，极端情况拉长控制周期。
**建议**：每轮最多处理 32 字符后 `break`，剩余下轮再收。

### 🟡 P3（体验 / 一致性，随版本清理）

5. **无本地回显**：终端敲字符看不到（:273-279 只入队不回显）。建议入队时 `debug_printf("%c", ch)`；退格时发 `"\b \b"`（现在退格只 `s_line_length--`，终端上字符仍显示，看起来"没删掉"）。
6. **注释过时**（v3 已提、仍未修）：`:115` "若 5s 无命令" → 10s；`:281-282` "5s 自动停功率""自动状态打印(150 行)" → 10s 与 :149。
7. **SET 在 FAULT 态仍可执行**：只拦 `requested()`（:195），未拦 FAULT。危害有限（START 有 FAULT 门），但语义应与 START/CLEAR 一致——建议拒绝或提示。
8. **错误文案硬编码阈值**：`:201` "voltage=32.3..85V" 与 llc_control.h 宏重复。建议改为"超出 LLC 参考范围（LLC_CV/CC_REFERENCE_*）"，或保留数值但注明需与宏同步。
9. **`COMMISSIONING_USE_UART`（main.h:108）未真正门控**：量产移除控制台的开关没接线。建议用 `#if COMMISSIONING_USE_UART` 包裹本文件实现，或在 main.c 用它决定是否调 `serial_console_init/task`。
10. **init 未打首帧状态**：`serial_console_init`（:251-258）只打 HELP，不像 CAL 模式（:79）会打一帧状态。建议末尾加 `print_status(true)`，上电即见关键量。
11. **长充电与看门狗**：10s 无命令自停（:283-287）在长充电联调时仍需周期 PING。建议增加可选命令（如 `WD <sec>` / `WD OFF`）供 bench 使用并打印风险提示，默认保持 10s。

### ✅ 维持不变的结论
- 非阻塞收发架构正确；`%f` 需 MicroLIB/浮点 printf 支持（P1，人工确认项）；
- 命令行解析健壮（`\r\n` 去重、退格/DEL、小写转大写、64B 长度保护）；
- CLEAR 与 `protect_fault_active_hw()` 的联动约束仍挂起：恢复硬件轮询时，`:235-238` 被注释的拒绝分支必须同步恢复；
- STOP/START/CLEAR 的安全门（运行中禁改、故障态禁启、未设参考禁启）逻辑正确；
- HELP 文案已同步为新范围（`SET <32.3..85V> <above-0..20A>`，:124）✓。
